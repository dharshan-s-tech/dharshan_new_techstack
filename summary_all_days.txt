**`ENCRYPTION_KEY` is actively used in the application as a 256-bit (32-byte) symmetric encryption secret key** for two-way AES-256 encryption and decryption.
 
---
 
### 1. Where and Why It Is Used
 
#### A. Subscriber Email Verification & Verification Tokens (`SubscribersController.php`)


When citizens subscribe to CAG email alerts/newsletters on the portal:


1. **Generating Secure Verification Links**:


   Instead of exposing the raw database ID in public links (which would allow attackers to guess IDs and confirm subscriptions on behalf of other citizens), the system encrypts the subscriber's ID:


   ```php


   // When user subscribes:


   $token = Security::encrypt($subscriber->id, ENCRYPTION_KEY);


   // An email is dispatched with link: /subscribers/subscribe/<encrypted_token>


   ```


2. **Decrypting Callback Links**:


   When the citizen clicks the verification link in their email, the controller decrypts the token back to the subscriber record using the same key:


   ```php


   // When user clicks verification link:


   $token = Security::decrypt($token, ENCRYPTION_KEY);


   $subscriber = $this->Subscribers->find()->where(['id' => base64_decode($token)])->first();


   ```
 
#### B. Cryptographic Payload & Token Obfuscation


`ENCRYPTION_KEY` is used whenever data needs to be safely transmitted through public URLs or untrusted clients and later recovered on the server without tampering.
 
---
 
### 2. Why Is It Configured as an Environment Variable?
 
During the CERT-In / security compliance remediation:


1. **The Vulnerability**: Originally, `config/constants.php` had a hardcoded default key string in the codebase (`'<ENCRYPTION_KEY>'`). If anyone had read access to the source code, they could forge tokens or decrypt subscriber data.


2. **The Security Rule**: Government security guidelines mandate that symmetric cryptographic keys **must not be hardcoded in the repository**.


3. **The Current Enforcement (`config/constants.php`)**:


   ```php


   define('ENCRYPTION_KEY', getenv('ENCRYPTION_KEY') ?: (function() {


       if (getenv('APP_ENV') === 'production' && !getenv('DEV_MODE')) {


           throw new \RuntimeException('ENCRYPTION_KEY environment variable must be set in production');


       }


       return '<ENCRYPTION_KEY>'; // Local dev fallback only


   })());


   ```


   In production, the application will refuse to boot if `ENCRYPTION_KEY` is not supplied in the environment.
 
---
 
### 3. Difference Between `SECURITY_SALT` and `ENCRYPTION_KEY`
 
| Configuration Key | Type | Primary Purpose |


|---|---|---|


| **`SECURITY_SALT`** | One-Way Salt | Used for **one-way hashing** (SHA-512 password hashing, CSRF tokens, session anti-tamper cookies). Data hashed with salt *cannot* be decrypted. |


| **`ENCRYPTION_KEY`** | Two-Way AES Key | Used for **symmetric encryption & decryption** (AES-256). Data encrypted with this key *can* and *is* decrypted back to its original value on the server. |
